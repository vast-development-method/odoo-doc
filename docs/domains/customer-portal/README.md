# Customer Portal

The Customer Portal is the self-service front end through which people who are not employees of the operating company reach the records that concern them. It gives a customer, a vendor, a project collaborator or an event attendee a signed-in area ("my account") that lists their quotations, orders, invoices, bills, projects, tasks, timesheets and loyalty balances; it gives every business document a stable public web address protected by a per-record security token, so that a document can be shared by electronic mail with a person who has no account at all; it gives the operating company an invitation workflow that turns a Contact into an external user and an equally simple revocation; it carries the discussion thread (messages, attachments, reactions, ratings) onto those public pages with an identity that is proved by a signed token rather than by a session; and it owns the account self-management pages where an external person changes their password, enrolls a second authentication factor, registers a passkey, revokes their sessions, manages their addresses and asks for their account to be deleted.

This domain owns the *frame*: the layout, the navigation, the list-page contract (pagination, sorting, filtering, grouping, date ranges, free-text search), the record-page contract (sidebar, previous/next navigation, report rendering and download, discussion thread, signature block), the token model and its validation, the invitation and revocation wizards, the share wizard, and the account pages. It does not own the documents themselves: the Sales, Accounts Receivable, Accounts Payable, Purchasing, Projects and Tasks, Timesheets, Events, Manufacturing, Loyalty and Customer Relationship Management domains each contribute their own pages by implementing the contract described here.

## Business scope

The domain delivers the following capabilities.

1. **External user identity**: the portal access group, the `share` characteristic that distinguishes an external user from an employee, the binding of an external user to exactly one Contact, and the redirection rules that send an external user to the portal home instead of the back office on sign-in and on every attempt to open a back-office web address.
2. **Invitation and revocation**: a wizard that takes a selection of Contacts (and, for a company Contact, its child Contacts of kind `contact` and `other`), shows for each one the electronic mail address, the latest authentication moment and the current access state, validates the address for format and for uniqueness against existing logins, creates an external user from the portal user template in the Contact's company when none exists, adds the portal group and removes the public group, prepares a sign-up token on the Contact, and sends the invitation message that carries an "activate account" link; plus a revocation action that archives the external user, clears the sign-up token and keeps the portal group; plus a re-invitation action that regenerates the token and resends the message.
3. **Per-record public access**: an access mixin that any document model may adopt; it adds a portal web address computed by the owning model, a security token generated on first demand and never copied when the record is duplicated, and an access warning that the owning model may fill to block sharing; it builds share web addresses with the token, with an optional sign-up parameter and with an optional signed recipient identity; and it changes the "open this document" action so that an external user, or anybody when a front-end redirection is forced, is sent to the portal page instead of the back-office form.
4. **Document sharing**: a wizard opened from any document that carries the access mixin, showing a ready-to-copy share link, accepting a list of recipient Contacts and an optional note, refusing to send when the document declares an access warning, and choosing per recipient between a plain token link (recipient already has a user, or the document has a token) and an individual sign-up link (recipient has no user and free sign-up is enabled); each send posts an internal note on the document with the invitation body and notifies the recipient.
5. **Portal home**: a dashboard of document cards grouped into four categories (alerts, client documents, service documents, vendor documents) plus a common category with the address book and the security page; each card shows a live counter fetched asynchronously in at most three batched calls, hides itself when the counter is zero, and remembers in the session which counters were non-zero so that the next page load can show them immediately.
6. **Document list pages**: a single contract shared by all list pages, consisting of a breadcrumb or a title, a sort selector, a filter selector, a group-by selector, a scoped free-text search box, an optional date range, a page size of eighty rows, a page navigator with first, previous, numbered, ellipsis, next and last entries, and a session-stored history of the last one hundred identifiers that powers the previous/next navigator on the record page.
7. **Document record pages**: a shared frame that supplies the record, the token, the previous and next record links, the flash messages (error, warning, success), the recipient identity parameters, the sidebar with amounts and action buttons, the report rendering in rich-text, portable-document or plain-text form with an inline or attachment disposition, and the discussion thread anchor.
8. **Signature at the document level**: a reusable signature panel that posts a typed or drawn signature with a name to a document-specific endpoint; the owning domain decides what confirming a signature does.
9. **Discussion on portal pages**: message retrieval restricted to non-internal messages with a public subtype and a non-empty body or at least one attachment; a portal-specific message projection that returns author, body, date, attachments with their access tokens, reactions, starred flag, note flag and formatted publication date; posting with attachments by an anonymous visitor whose identity is proved by a signed token; editing one's own message; reacting; removing a pending attachment; and, for employees, toggling a message between public and internal.
10. **Ratings from the portal**: a star widget and a pop-up composer that posts a message carrying a rating value; a publisher comment that a website editor or a person with write access on the rated record may attach to a rating, stamped automatically with the publisher Contact and the publication moment; and the inclusion of rating values and per-record rating statistics in the portal message projection when requested.
11. **Account details and addresses**: a "my account" form that edits the signed-in person's own Contact, an address book that lists billing and delivery addresses reachable from the commercial entity, an address form that creates or updates a child address, per-country dynamic address layout (field order, required fields, subdivision list, telephone prefix), server-side validation of required fields, electronic mail format and tax identification number, protection of commercial fields on child addresses, protection of the country and of the tax identification number once documents have been issued, protection of the name and electronic mail address of employees, and archiving of a child address.
12. **Connection and security page**: password change with the old password required and the session token refreshed, the password strength meter and minimum length when a password policy is installed, second-factor enrollment and disabling with the trusted-device list, passkey registration, renaming and deletion, revocation of all other sessions behind a re-authentication gate, application key creation and deletion when the operating company allows it and the developer mode is active, and the account deletion request.
13. **Account deletion**: a confirmation dialog that requires the current password and the exact login typed back, with an opt-in request to add the electronic mail address and telephone number to the block lists; the account is renamed to a reserved deleted-account login, the password is emptied, the application keys are removed, the user and the Contact are archived, a note is logged on the Contact, and a deletion request is queued for the daily scheduled job that actually removes the user and then the Contact.
14. **Front-end presentation services**: the portal layout with its navigation bar, user menu, skip-to-content link, language selector, breadcrumb, full-width alert, offcanvas account sidebar, "powered by" credit and social preview metadata; the language switch that rewrites the current web address in the chosen language; and the marking of layout variants that a website editor may enable or disable.

## Actors

| Actor | Access group (canonical identifier) | What the actor does in this domain |
|---|---|---|
| Anonymous visitor | `base.group_public`, labelled `Role / Public` | Opens a shared document web address carrying a valid security token, reads it, downloads its report, posts a message or a reaction when a signed recipient identity is supplied, signs a document, and pays it through the payment pages. Never sees the portal home, the address book or the security page. |
| Portal user (external user) | `base.group_portal`, labelled `Role / Portal` | Signs in, sees the portal home and its counters, browses the document list pages and record pages allowed by the record rules of each document domain, posts messages, rates, signs, pays, edits their own Contact and their addresses, manages their password, second factor, passkeys, sessions and application keys, and requests the deletion of their account. |
| Internal user (employee) | `base.group_user`, labelled `Role / User` | Sees the same portal pages (the portal is not hidden from employees) but is subject to the same "no internal messages" restriction on portal discussion threads; may toggle a message between public and internal; may not change their own name or electronic mail address through the portal address form. |
| Contact manager | `base.group_partner_manager`, labelled `Creation` under the privilege `Contact`; implied by `base.group_system` | Opens the portal access wizard from one or several Contacts, grants, revokes and re-sends invitations, and opens the share wizard on a document. |
| Website editor | `website.group_website_restricted_editor` | Publishes a comment under a rating shown on a public page, and enables or disables the optional layout variants of the portal templates. |
| Settings administrator | `base.group_system` | Enables or disables the setting that lets external users create application keys. |
| Scheduler | runs as the system robot user | Executes the daily queued deletion of external accounts. |

## Entities owned by this domain

| Canonical name | Identifier | Kind | Purpose |
|---|---|---|---|
| Portal Access Mixin | `portal.mixin` | abstract | The contract adopted by every document model that is reachable from the portal: portal web address, security token, access warning, share web address construction and access action override. |
| Portal Share Wizard | `portal.share` | transient | Collects the recipients and an optional note, exposes the copy-ready share link, and sends one invitation message per recipient. |
| Portal Access Wizard | `portal.wizard` | transient | The container of an invitation session: the selected Contacts, the derived per-Contact lines and the free-text welcome message added to the invitation. |
| Portal Access Wizard User | `portal.wizard.user` | transient | One line of the invitation session: one Contact, its editable electronic mail address, the linked user if any, the latest authentication moment, the derived access state, the grant, revoke and re-invite actions, and the three extension points that decide whether the typed address is already used as a login. |
